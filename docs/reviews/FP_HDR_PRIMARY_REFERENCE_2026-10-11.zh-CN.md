# Sigma fp HDR：增益图必须绑定最终 SDR 主图

执行日期：2026-10-10 America/Los_Angeles / 2026-10-11 UTC。定位基线：`1f3c8af6c3a9d09b188ebd47f6d88d418c07980a`。本记录补充 [Core Image half / float 读回研究](COREIMAGE_HALF_READBACK_2026-10-11.zh-CN.md) 中 fp HDR99/420 的交付负例。

**根因在 HDR 封装时的主图参考，不在默认 half 解码。** 原先先依据未压缩 SDR 母版生成增益图，再将容器主图替换为 x265 编码的 SDR。主图有损编码改变了局部颜色和细节，原增益图仍引用替换前的图像；展开 HDR 时，这部分主图差异随增益一起进入结果。使用同一份最终 x265 主图的实际解码结果作为增益图参考，可以在保留原 SDR/HDR 母版、99/420 参数和全部生产门限的条件下修复本例。

这不是“所有 4:2:0 都有问题”，也不是改用 float 就能解决。前轮直接 half、最近舍入 half 和 float 三种输入均触发同类拒绝。此次使用原始 RAW 重新形成默认 half 母版，隔离 HDR 封装步骤；没有改变 AgX、曝光、白平衡或高光计划。

机器汇总记录：[fp-hdr-primary-reference-20261011.json](../assets/delivery-quality/fp-hdr-primary-reference-20261011.json)。下文区分同母版隔离对照与完整 RAW 生产入口，不将两者计为不同相机画质样本。

## 为什么替换主图会影响 HDR

忽略 ISO gain-map 的偏移项、编码曲线及量化，用线性域的简化关系说明：原 SDR 参考为 \(B\)，目标 HDR 为 \(H\)，增益近似 \(G=H/B\)。若最后实际主图变为 \(P\)，却保留原增益，展开结果近似为

\[
P\,G = H\,(P/B).
\]

即使 \(P\) 对 SDR 预算足够接近 \(B\)，局部的 \(P/B\) 仍可能破坏 HDR 纹理；主图和增益图各自质量高，并不足以保证两者组合正确。实际修复不手写上述除法、不对近黑像素裸除，也不推断 Apple 内部具体实现。它让 Apple 使用最终 SDR 主图的真实解码 CIImage 和原 HDR 母版重新生成符合容器合同的辅助图。

参考图通过同一主图 donor 的 URL 加载，明确关闭 HDR 展开，保留其颜色解释，再将内容 headroom 标记为 1。生成辅助图后装回**同一份**已编码主图。不能拿另一个候选、同参数但不同像素的文件，或另一次不确定的编码结果替代参考。

本次主图重建没有改变两个原母版。SDR 仍对最初 float32 SDR 母版验证，展开 HDR 仍对最初 packed half HDR 母版验证；尺寸、P3 ICC、10-bit、请求采样、RGB ISO gain map 和真实峰值声明也继续核对。修复没有将显示容量 8 当作实际内容峰值；本例的真实 packed 峰值及文件声明均为 1.8212890625。

## 生产修复的边界

生产接入采用有界回退：仅适用于**非 Archive 档位的 float32 SDR base + 10-bit HEIC + x265 主图**，Archive 不启用此回退。先保持原候选和辅助质量重试阶梯；只有 HDR 回读仍失败时，才对该最终主图建立一次新的参考并重新生成辅助图。自动搜索只允许辅助质量 100 的候选使用此回退，避免每个较低质量候选都重复建立参考。它不是把所有失败换成成功，也不吞掉源事务、主图验证、容器或 I/O 错误。

模板必须绑定具体 donor 身份；禁止跨主图复用已经重建参考的模板。最终仍要验证实际主图 payload 与必要属性，确保计算辅助图所用参考就是装入文件的主图。再次失败仍拒绝发布，保留源 RAW 保护和原子提交。

`gainmap_reference_identity` 标识辅助图生成、搬运拍摄元数据之前的 donor。完整 CLI 最后搬运元数据时会调整描述属性顺序及相同 ICC 的 essential 标志，因此更保守的阶段身份 hash 可以改变；本例主图、辅助图、ISO tmap 载荷、属性内容和 HDR 关系的规范化编码内容签名保持相同。该阶段执行容器检查及编码内容不变检查，不冒充第二次完整 HDR 像素回读。最终文件 SHA 与生成阶段参考身份分别记录。

验收另对最终 fp unity 文件执行一次独立全尺寸 HDR 像素回读，与最初 packed HDR 母版比较；全部原 HDR 门限通过，各项指标与搬运元数据前逐项相同。该最终文件 SHA-256 为 `784c040f49cefc064d1ab84520b3b8385677e44b732946b3f59220e0622f23db`。这一次额外回读不外推成 Sony/Nikon 也重新执行了同样的末端像素检查。

以下行为保持：默认 half 解码、原 SDR/HDR 母版、形成计划、主图质量与采样请求、输出尺寸、全部生产回读门限。此项不默认开启额外降噪，不引入锐化，也不把主图 420 静默升级为 444。

## 可复用的完整 RAW 复现

使用 SHA-256 与上述记录一致的原始 fp 文件。以下参数已通过 CLI 解析检查；真实解码与编码需要相应 macOS Core Image/ImageIO 和项目 x265 后端。固定 token 9，不允许自动回退后冒充同一实验。

```sh
mkdir -p /private/tmp/agxraw-fp-hdr-repro
DNGSCAN_FAST=1 python -m dngscan /path/to/_SDI0016.DNG \
  --decoder coreimage --coreimage-version 9 --coreimage-scale unity \
  --wb camera --ev auto --scene-transform none \
  --output-format ultrahdr-heic --delivery-profile share \
  --jpeg-quality 99 --chroma 420 \
  --heif-encoder x265 --heif-bit-depth 10 --heif-preset slow --heif-tune ssim \
  --hdr-headroom 3 --output-gamut p3 \
  --jpeg /private/tmp/agxraw-fp-hdr-repro/fp-share99-420.heic --report
```

生产默认 aligned 应另运行一组：仅将 `--coreimage-scale unity` 换为 `--coreimage-scale aligned`，并使用另一个输出文件名。两种尺度可能改变分析和计划，不能将其差值混成封装步骤的数值差。正常的 auto 编码档也须单独验收，不以固定 share99/420 的结果代替。

定位探针在开发隔离目录中调用生产形成、writer 和原门限；为了观察被拒候选，私有调试钩子保留了模板和拒绝前文件。这些文件不属于正常产品发布结果，失败文件没有通过公共出口发布。探针不是新增用户命令，也不提交私人 RAW、NPY、HEIF 或裁图。
