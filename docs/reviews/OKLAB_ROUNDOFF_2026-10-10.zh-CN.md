# SDR Oklab 过零精度约定与实拍复核

日期：2026-10-10。基线为 `ad57ea2` 加本轮工作区修改；本记录不宣称独立解码器准确性或实测传感器标定通过。

## 原因与最小反例

iPhone 16 Pro 的 `Original RAW 26-07-11 202403093.dng`（SHA-256 `9d53f9a850f7935d1751a2f6f75e21fc93e27a8acf3a610819da852962b05dde`）全尺寸双后端的 scene 逐位一致，但 SDR 最大误差为 `4.352629e-4`。用同一份 NumPy 分析、固定计划及相同 pre-DRT 像素复查，差异来自输出色域拟合，不是计划统计、RAW 解码或新增色度清理。

以下两行独立 Display P3 线性 RGB 已足够复现，无需 RAW：

```python
rgb = np.asarray([
    [.1406678855419159, -.01818111352622509, -.011180703528225422],
    [.1406678706407547, -.018181087449193, -.01118070911616087],
], np.float32)
encoded = encode_display_linear(fit_to_output_gamut(rgb, "p3", alpha=.045), "p3")
```

旧实现第三 LMS 分量分别约为 `-6.81e-10` 与 `+3.07e-10`。有符号立方根在零点附近条件很差，微小矩阵抵消误差被放大，再影响色域拟合。仅把 Oklab 改为 float64，仍不能保证已经物化为 float32 的上游 RGB 获得稳定结果。

## 数学约定与变更范围

令 `A=RGB→XYZ`、`B=XYZ→LMS`，两次矩阵乘法用 float64 系数及累加、各自物化为 float32。保留这两步，而非在 Rust 中预合并前向矩阵。设实际存储结果为 `x, z, l`，`u=eps32/2`、`v=eps64/2`，采用逐分量前向舍入界：

```text
r = u/(1-u) + 3v/(1-3v)
bound = r * (|B||A||x| + |B||z| + |l|)
```

只在 LMS 和误差界都有限、且 `abs(l) <= bound` 时，将该分量规范为零；区间以零对称，区间外原符号和数值保留。该约定描述 float32 存储及矩阵相消的数值精度，不是物理噪声阈值，不裁掉显著负 LMS，也不把未知信号解释为正值。误差界随正常范围内的全局增益同比缩放。非有限矩阵结果不参与规范化，避免 `inf <= inf` 把 overflow 伪装成零；未重定义既有巨幅输入和异常值处理合同。

修改仅涉及 Python Oklab 前向入口、Rust 输出色域拟合及计划参数，native ABI 升为 22；逆矩阵仍遵守原近似合同。AgX 的曝光、punch、端点、颜色意图、色域拟合 alpha、迭代次数与现有 `1e-4` 验收阈值没有改动。色域内像素的原样通过路径保持。

归零区间边界仍是一个明确的数值约定：跨出区间的不同 RGB 不被宣称等价，有符号立方根在区间外仍可能敏感。这不是对任意微扰的全局连续性保证，不能靠扩大区间或放宽验收掩盖新的反例。

## 验证与限制

新增回归覆盖原两行 RGB、正负 ULP 邻点、明显正负 LMS、全局增益、色域内恒等、非有限／巨幅矩阵结果保留及 NumPy/native 随机色域拟合。Rust 单测另检查 overflow 不能归零。

重建 ABI 22 后，对上述 iPhone 文件全尺寸重新执行真实 LibRaw、分析、SDR/HDR 成像双后端验证：scene 最大差为 0；SDR 最大差降为 `7.420778e-6`，各通道 RMSE 为约 `[3.95e-8, 2.84e-8, 2.52e-8]`；HDR 最大差 `5.483627e-6`，与修改前相同。独立两行 RGB 的编码后差降为 `1.49e-7`，两后端结果一致。该实拍探针使用本轮工作区代码，完整五个 RAW 的正式报告及全量发布 gate 另行记录。

巨幅输入审查确认正常有限值的误差区间之外不改 LMS；NaN、Inf 及有限 float32 极值引发的矩阵 overflow 不因新约定被清零。既有异常输入／finalizer 回退回归也独立执行。未借此扩展为任意非有限输入可显影的产品能力。
