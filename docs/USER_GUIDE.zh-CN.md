# dngscan 使用说明

[修图教程](EDITING_TUTORIAL.zh-CN.md) · [胶片教程](FILM_TUTORIAL.zh-CN.md) · [使用说明](USER_GUIDE.zh-CN.md) · [架构与技术细节](ARCHITECTURE.zh-CN.md)

这是一份不讲数学的说明书。它回答三个问题：这个工具能处理什么相机的照片、界面上的每个数字是什么意思、导出时该选什么。想了解管线原理和技术细节，请看[架构与技术细节](ARCHITECTURE.zh-CN.md)。[English version here](USER_GUIDE.md).

dngscan 做一件事：把 RAW 照片转成尽量忠实的 JPEG——普通 JPEG，或者在支持的屏幕上能真正亮起来的 HDR 照片（iPhone / Mac / 新款 Android 相册都能直接看）。

---

## 一、支持哪些相机

**默认解码器（LibRaw）**覆盖市面上绝大多数相机的 RAW 格式，包括但不限于：

| 品牌 | 格式 |
|---|---|
| 佳能 | CR2 / CR3 |
| 尼康 | NEF / NRW |
| 索尼 | ARW |
| 富士 | RAF（含 X-Trans 传感器） |
| 松下 / 奥之心 / 徕卡 / 宾得 | RW2 / ORF / DNG / PEF 等 |
| 适马、iPhone（ProRAW）及一切输出 DNG 的设备 | DNG |

装好就能用，不需要按机型安装插件。本工具的开发与校准主要在适马 fp 的 DNG 和 iPhone ProRAW 上完成，这些机型的体验经过最充分的验证；其余主流机型可以正常解码转换，遇到异常欢迎反馈样张。

**太新的机型也能用**：刚发布、内置数据表还没跟上的相机（如 A7 V、GR IV、X-E5 这一代）不会被拒绝——工具会自动降级并在报告里明确提示"该机型标定数据不完整，结果可能有偏差"，照片照常导出。部分新机型（A7 V / A7S III / A7R VI / GR IV / 尼康 Zf / X100VI / X-E5）已内置实测传感器数据，并在有已发布系数的机型内置颜色矩阵——A7R VI 的矩阵宁缺毋猜（走声明降级路径），GR IV 由 DNG 自带标定。

**一个已知例外：尼康高效压缩（HE/HE\*）NEF**。Z9/Z8/Z6III/Z50II 世代如果拍摄时选了"高效压缩"，该格式因编码授权问题无法被 LibRaw 解码（全行业开源工具皆如此），报错时工具会给出具体指引。解决办法：用免费的 Adobe DNG Converter 把文件转成 DNG（转换后全功能可用），或在相机里改用"无损压缩"RAW。同机身的无损 NEF 一切正常。

**Apple RAW 解码器（可选，"解码器"选 Apple RAW）**使用 macOS 系统自带的 RAW 引擎，支持范围以 Apple 官方的相机 RAW 兼容列表为准——主流的佳能、尼康、索尼、富士、松下、适马机型和 iPhone 都在内，但**最新版解码模型（RAW 9）只对其中较新的机型开放**。不用自己查列表：选中文件后工具会自动探测这个文件支持到哪个版本，不支持时会明确提示并让你选择降级或改回 LibRaw，不会不吭声地换算法。

这里切换的只是画面重建方式。检测参数所依据的传感器 Evidence 始终由同一版 LibRaw
获取，切换 LibRaw / Apple RAW 不会改变 Evidence；如果 LibRaw 连文件都打不开，Apple
RAW 也不会绕过这个分析前提。

两个解码器出片的色彩性格略有不同（Apple 的降噪和高光重建更"相机厂商化"），都可以正常出 SDR 和 HDR。不确定就用默认的 LibRaw。

RAW 解码卡上还有两个不常动的解码级选项，性质各不相同。**CI 尺度**（CLI `--coreimage-scale`，只在解码器选 Apple RAW 时出现）决定 Core Image 输出的场景线性数值按什么尺度进入后续管线："对齐 LibRaw · 默认"逐文件对齐 LibRaw 解码的结果，"原生单位"保留 Core Image 自己的单位，"实测补偿"是旧版的固定倍率、只为复现早先的结果保留；改它会重做准备（解码级）。**剪切回退 DN**（CLI `--margin`，整数 0–64，默认 4）是每个通道的满阱剪切阈值从满阱向下回退的 DN 数——它不改变画面重建，改变的是分析判据：RAW 剪切百分比、"RAW 满阱"旁的硬剪切数字乃至整张检测参数卡都按它重算，所以改它会重做分析。两者日常都不需要动；导出文件名只在非默认时带上 `ciscale-unity` / `ciscale-measured` 或 `margin{n}` 标记。

## 二、基本流程

1. **选文件**——顶部选择 RAW 文件；
2. **看"检测参数"**——工具已经分析了这张照片，先看这里再动手（下一节解释每个数字）；
3. **调曝光和明暗**——需要的话。拿不准高光该压曝光还是调肩部时，先打开预览卡上的"**RAW 满阱**"开关看一眼（第三节末尾）；
4. **选输出**——普通 JPEG 还是 HDR，发朋友圈还是存档（第十节）；
5. **更新预览确认，导出。**

界面上没有"分析报告"这一项：GUI 只出图，导出后的"投递报告"只列 HDR 容器的实测事实（第十节）。想看完整的分析报告——证据、曲线端点、色彩矩阵健康度 κ、Stage A 残差等——用命令行加 `--report`；不加时命令行默认只打印写出的文件（`JPEG 图像: …` / `PNG 图像: …`），带 `--scan` 或 `--csv` 的诊断运行会自动附带报告。

除这类报告/诊断输出（`--report`、`--csv`、`--support`、`--hdr-debug-dir` 等）外，GUI 已覆盖命令行的全部可调项：成像上能在命令行调的，界面上都有对应控件，按状态隐藏或置灰的只是当前不适用的那些（第十一节）；六面板分析图可在导出对话框勾"附带分析图"顺带生成（第十节）。

## 三、"检测参数"里的数字是什么意思

这张卡显示的是工具对照片的测量结果，和最终渲染用的是同一套分析。

**先弄懂 EV**：EV 就是"档"，摄影里的曝光单位。+1 EV = 亮度翻倍，−1 EV = 亮度减半。本工具里所有 EV 都以**中灰**（曝光正确的 18% 灰，大致是正常曝光下人脸中间调的亮度）为 0 点：+3 EV 表示比中灰亮 3 档，−5 EV 表示比中灰暗 5 档。

| 字段 | 意思 | 有什么用 |
|---|---|---|
| **RAW 剪切** | 传感器上有多少比例的像素过曝溢出（"死白"） | 高说明高光烧了不少；这部分像素的颜色是猜出来的，工具会自动降低对它们的信任 |
| **可靠高光尾部** | 照片里最亮、且**真实测到没烧掉**的内容在几档（剪切像素已剔除，不算数） | 这是 HDR 亮度预算的唯一依据：夜景灯牌测到 +6 EV，HDR 就有底气把它点亮到 +6 |
| **HDR 可挣余量** | HDR 可用的额外亮度：可信的最亮信号里超出"纸白"（屏幕上正常白色）的部分 | 就是这张照片 HDR 能比普通照片额外亮多少档；为 0 说明这张图没有值得 HDR 的高光 |
| **主体中位** | 画面主体大致在几档 | 负得多说明整体偏暗（夜景），接近 0 说明曝光标准 |
| **场景类型** | 普通 / 稀疏光源 | "稀疏光源"= 夜景灯点、舞台这类大片黑+小片极亮的场景，工具会自动换一套更合适的高光策略 |
| **编译曲线** | 本次渲染实际生效的曲线：暗部到亮部范围和对比度 | 参考值，让你知道工具替这张图做了什么决定 |

**看这张卡的典型方式**：可挣余量 +1.5 EV → 值得导 HDR；RAW 剪切 8% → 天空可能烧了，过曝区会被自动降权处理；主体中位 −3 EV → 这是夜景，别硬拉曝光。

### "RAW 满阱"：过曝在哪里、是哪个通道

"RAW 剪切"那个百分比只说有多少像素烧了，不说烧在哪里、烧的是哪个通道。预览卡右上角的"**RAW 满阱**"开关补上这一层：打开后，RAW 里达到满阱 97% 以上的像素（渲染里色度退让生效的区域——接近满阱，未必已经溢出）按 CFA 通道直接标在预览图上——**红/绿/蓝 = 该通道接近满阱，白 = 三通道都接近满阱**；开关旁显示两组数：**硬剪切 R · G · B**（全尺寸统计，≥满阱−margin，与检测参数卡"实测 RAW 剪切"同一判据，这才是"过曝了多少"的权威数字）和**标记区占比**（≥97% 满阱，标记层覆盖的面积）；没有这类像素时显示"无 ≥97% 满阱像素"。

它标的是**解码证据，不是渲染结果**：数据来自渲染时做剪切退让和 HDR 色度门控的同一份证据掩码，由解码派生、与白平衡无关，每次准备预览取一次，之后叠在每一帧实时预览上。所以它**不随曝光滑条变化**——把 EV 拉低，画面暗下去，标记纹丝不动，因为它记录的是传感器上的位置，不是渲染亮度。标记区里有多少像素真的没有信息，看旁边全尺寸的硬剪切百分比——软掩码经过羽化和缩放，标记像素本身可能仍保有有效数据。

这正是它的用法：**分清"RAW 里贴着满阱"和"只是渲染得太亮"**。高光看着刺眼，先开这个开关。标记稀疏或没有，说明 RAW 离满阱还远，那是曲线的事——去明暗卡调肩部（肩部收白、高光过渡，第七节）或适当压 EV，层次都能回来。大片白色标记（三通道都贴着满阱）配上不低的硬剪切百分比，那块区域在 RAW 里就已经是一片平，压 EV 只会把它变成一片灰，调肩部也变不出层次——要么接受它是"死白"，要么交给第九节的 AgX 让它自然褪向白；硬剪切百分比接近零时，标记区仍有数据，压 EV 能把层次拉回来。只有一两个通道的彩色标记，说明那里的颜色靠剩余通道支撑，工具已经自动降低对它们的信任（色度退让）；局部颜色不对劲时先看这一层，再怀疑别的设置。

用 Apple RAW（Core Image）解码时这个开关是灰的，旁边写着原因：Core Image 解码没有逐像素 CFA 证据，过曝显示不可用。

## 四、白平衡：拍摄值与固定色温

白平衡下拉里除了"拍摄值"，还有一组**固定色温**选项。它们不是让你用眼睛调白平衡——肉眼在屏幕前找"准"永远赢不了相机的机内测光（人眼自己会色适应）。它们是**标准参考值**：数值来自各行业的固定标定，配平系数由照片文件自身的颜色标定精确求解，全程没有眼睛参与。

| 选项 | 这是什么 | 什么时候用 |
|---|---|---|
| **拍摄值 · As Shot** | 相机拍摄时测定的白平衡 | 默认；日常出片 |
| **6500K · D65** | sRGB/Rec.709 显示器的标准白点 | 想和显示行业标准对齐时 |
| **5500K · 摄影日光** | 日光卷胶片的标定色温 | **胶片模拟的正确起点**：整卷统一 5500K，现场光的暖冷如实穿过，钨丝灯下就该偏橙——和真胶片一致 |
| **3400K · Type A** | Type A 钨丝卷（photoflood 摄影灯） | 钨丝灯胶片模拟 |
| **3200K · Type B** | Type B 钨丝卷（影棚钨丝/卤素灯） | 同上，更常见的钨丝标定 |
| **9300K · 日本广播白点** | 日本电视行业的传统白点（偏冷蓝） | 想要"日本老电视"的冷调观感，for fun |

固定色温两种解码器都支持。选了固定色温后画面出现色偏是**预期行为**——这正是胶片看世界的方式，不是故障。

## 五、选一卷胶片（GUI"胶片观察位置"；20 款胶片 + 5 款影院变体）

先说清楚：**这不是一键滤镜**。它是把"一卷胶片如何看世界"拆成几层独立设置的
系统，好处是每一层都能单独理解、单独调整；代价是需要花两分钟建立心智模型。
这两分钟就是下面这几段。想看每个胶片控件配实拍对比图的逐一讲解（含放大机色头、"色彩由谁负责"与胶片色偏），见《[胶片调整说明书](FILM_TUTORIAL.zh-CN.md)》。

### 心智模型：胶片决定"看见什么"，AgX 决定"怎么显影"

选中一款胶片时，界面上有五个控件被同时设置（**全部可见、全部可改、没有任何
一层被烘焙**）：

| 层 | 它做什么 | 什么时候需要动它 |
|---|---|---|
| **白平衡**（RAW 解码卡） | 锁定该卷的标定色温：日光卷 5500K、钨丝电影卷 3200K | 钨丝灯下画面偏橙是**设计如此**（真胶片就这样）；不想要这个效果就改回"拍摄值" |
| **光谱前馈**（前馈卡） | 这款胶片的感色特性——感色层如何**分离**颜色（肤色、植物的分离性格），来自厂商数据手册 | 一般不动；想彻底关掉胶片的色彩分离就选 none |
| **前馈强度**（滑块） | 分离性格的浓度。胶片组合会按卷设一个推荐值（如 Velvia ×1.6） | **嫌风格淡→往上推，嫌浓→往下拉**。1.0=校准强度，推荐值是编辑口味不是测量 |
| **显影曲线**（明暗卡） | 该卷+配对显示介质的音调签名：黑位、宽容度、高光滚降。整卷固定，不随场景自适应 | 一般不动；配合"明暗微调"可在预设坐标附近修 |
| **AgX 原色几何**（成像卡） | 饱和与密度的"浓"：base/punchy/muted。组合按卷配对（Velvia→punchy、Kodachrome→muted） | **想要更冲/更收敛就切这里**，它是比前馈强度更大幅度的风格杠杆 |

颜色最终怎么"显影"到屏幕（高光怎么褪白、纯色怎么走）始终由 AgX 负责——
这是管线里被验证得最充分的部分，也是这套胶片模拟稳定的原因。

### 快速上手三步

1. 选一款胶片，直接导出看效果——组合预设已带推荐风格；
2. 觉得味道不对：**淡了**→前馈强度上推或原色几何切 punchy；**浓了**→反向；
   **色温倾向不喜欢**→白平衡改回拍摄值（只保留胶片的分离与曲线）；
3. 想比较"没有胶片"的基准：胶片选"无"即回纯 AgX。

### 常见意图对照

- 想要浓郁风景片 → Velvia 100（默认已配 punchy+×1.6）
- 想要柔和人像 → Portra 400（想更柔可切 muted）
- 想要克制复古 → Kodachrome 64
- 想要"影院拷贝原样上监视器"的高反差 → 带 **·影院放映外观** 的变体
- 想要电影负片的宽容平淡（扫描台风格）→ Vision3 系
- 只想要胶片的音调、不要色彩分离 → 前馈选 none、保留曲线预设

### 需要知道的边界

- 反转片/电影卷为**黑暗放映厅**设计（对比高约 1.5 倍），导出到日常屏幕时已按
  经典观看条件做外观折算——折算只含环绕项；标定描述的是**介质本身**（黑位=
  相纸/幻灯自身的 Dmax），观看环境的杂光不再烘进胶片曲线；
- **两种显影分工**（成像卡"显影分工"，CLI `--film-mode observe|full`）：默认
  "**观察 · AgX 显影**"即上述全部，日常用它；"**接管 · 胶片显影链**"让胶片显影
  模型整体接管，控件多出一整排——下一小节专门讲；
- 不加暗角——改变的是"这台相机看世界的方式"；颗粒、halation 只在接管模式的
  "模拟光学"里按声明启用，观察模式下没有；
- **HDR 照常工作**：观察模式一如既往；接管模式的 Ultra HDR 是
  "胶片印相 + scene HDR 扩展"——SDR 底图就是胶片印相（逐字节一致），
  参考白之上按场景自身可靠高光平滑增益，不声称物理胶片 HDR。

### 接管 · 胶片显影链（"显影分工"选"接管"后出现的控件）

观察模式里胶片只负责"看见什么"，颜色仍由 AgX 显影；接管模式把显影也交给
胶片：场景颜色先经该卷的 Stage A 折算为三层乳剂曝光（每卷按 held-out 交叉
验证选定曝光齐次的色度场修正，或色度场未过门时的约束 3×3 观察者；报告写明
用的是哪一个及其残差），过特性曲线得负片染料密度，再走因式分解的印相链：
负片密度 → 相纸层曝光 → 印相 timing → 相纸显影 → 观看色彩。AgX 只保留
交付端的色域安全，所以选接管后压缩核心锁定为 AgX。光源假设固定为
D55——实测表明白平衡之后钨丝与高显色 LED 场景与日光同级，所以**没有光源
档位**可选。这条链（film v2）、外观层、光学 V2 与观察模式都已落地（状态见
[docs/README.md](README.md) 的计划表），GUI 里不再标"实验"。

GUI 控件上的一句话说明是刻意写得很基础的，完整含义在这里：

- **灰阶中性化**（CLI `--film-neutralization`）：灰阶怎么回到中性。
  "**跟随胶片解释 · 默认**"按"胶片解释"解析——技术中和 → 数字中性，参考印相
  → 印相平衡（扫描对照变体的配方声明数字中性，编译器随之）；CLI 不给这个参数
  时同样交给编译器按胶片解释解析。"**数字中性**"（`technical-neutral`）：链的
  输出按像素亮度曝光除以随包的有界中性染色曲线，灰阶在偏中性两档以内严格
  保持中性；"**印相平衡**"（`print-balanced`）：只在 EV0 锚点解一次常数平衡，
  中灰依构造中性，灰阶两端保留介质自身曝光相关的 crossover；"**数据手册
  漂移**"（`native`）：链原样不做校正，中灰由印相求解锚定，阴影按各卷数据手册
  偏色——电影负片偏绿青、Kodachrome 偏琥珀、Velvia 温和偏冷。CLI 里
  `bounded`/`datasheet` 是 `technical-neutral`/`native` 的弃用别名；旧参数
  `--film-crossover off|datasheet` 同样弃用，`--film-crossover datasheet` 等于
  `--film-neutralization native`，两者同时给出会直接报错。
- **胶片曝光**（±2 EV，CLI `--film-exposure`）：乳剂相对标称 EI 的曝光状态
  ——拍这卷时是过曝还是欠曝——**不是输出曝光**。它改变的是负片本身（颜色、
  对比、趾肩），成片的总体亮度由下面的印相 timing 决定。
- **印相 timing**（CLI `--film-print-timing`）："**固定 · 默认**"沿用 EV0 联合
  求解的印相时间，胶片曝光变了也保持同一放大机设置；"**随胶片曝光重定时**"
  按暗房惯例随胶片曝光重新印相（从 0.25 EV 间隔的表插值），总体亮度接近
  不变、颜色/对比/趾肩随乳剂状态变化——对**全部 21 卷负片**（含影院放映外观
  变体）可用，只要该卷的重定时印相资产在；"**自定义 · 色头+印相曝光**"是手动
  印相：在固定 timing 之上加"印相曝光"滑杆（±2 EV，CLI `--film-print-exposure`）
  和放大机色头 Δτ（在相纸层曝光模型内解析，报告标 modelled）。自定义只对
  负片开放，并且要求灰阶中性化为"数据手册漂移"——手动印相的意义就是保留
  印出来的样子，GUI 会自动联动切过去（CLI 需显式配 `--film-neutralization
  native`）。反转片没有印相环节，timing 一律固定，另外两项置灰并给出原因。
- **印相介质**（CLI `--film-print-medium`）：默认为该卷的出厂配对相纸；只有
  烘焙了第二种介质的卷才出现这个下拉（本文写作时：Portra 400 另有 Supra
  Endura，Vision3 250D 另有 2393 拷贝片），换介质是同一张负片换纸重印，不会
  双重压缩。
- **胶片解释**（CLI `--film-appearance`，CLI 默认技术中和）："**技术中和**"是
  光谱链本体；"**参考印相 · 默认**"在链之上加该卷在配对相纸上的调色板外观层，
  配"解释强度"滑杆（0 = 不施加、1 = 配方声明值、最高 3 外推）；"**自定义**"是
  参考印相加三个有界修饰——丰度（−1…1）、色密度（−1…1，压亮不改饱和）、
  灰阶偏色（0…2，当前配方该场为零，预留）。参考配方覆盖仍窄：没有配方的卷，
  参考印相/自定义置灰、自动回到技术中和（本文写作时有配方的是 Portra 400、
  Ektar 100、Velvia 100、Vision3 250D）。
- **解释变体**（CLI `--film-appearance-variant`）："**参考印相 · 默认**"是印相
  解读；"**扫描对照 extended**"是 scan/telecine 对照解读——同家族方向、0.6 幅度，
  灰轴数字中性。只有做了 extended 资产的卷才出现这个下拉（本文写作时仅
  Vision3 250D）。
- **层间放大**（CLI `--film-interimage`）：显影耦合对色差的放大。"**声明 ·
  默认**"用该卷 modelled 表值（各卷声明范围 0.32–1.05）；"**关 · 光谱基线**"是
  纯光谱底座，调试口径；"**自定义 β**"露出 [0, 1.5] 滑杆（0 等效关），报告会标
  editorial dial。
- **模拟光学**（CLI `--film-grain/--film-halation/--film-bloom`）：三个档位
  "**关闭 · 默认** / **轻**（颗粒 0.25 · halation 0.20 · bloom 0.15）/ **标准**
  （颗粒 0.50 · halation 0.40 · bloom 0.30）"，或"**自定义**"三条 0…1 滑杆。
  三者是什么：**颗粒**是负片毫米坐标下的带限密度颗粒场，粒度响应用实测的
  σ(D)（按 5207 图表逐通道查表、48 µm 孔径校准），统计主场固定、每张照片随机
  一次空间排布，负片与相纸各取独立相位互不相关；**halation** 是高亮场景曝光经片基
  红敏背散射回注层曝光，发生在特性曲线之前；**bloom** 是进乳剂前的加性捕获
  辉光，声明为 editorial，不是守恒的介质散射。档位下拉旁另有两个小控件：
  **光学种子**（CLI `--film-optics-seed auto|N`）只决定颗粒的空间排布，不改粒径、
  频谱、密度响应和跨层协方差——留空即 auto，本次载入 RAW 时取一次固定种子，
  预览与导出因此一致（报告输出实际生效的 seed）；填一个非负整数则永远可复现。
  **介质散射**（CLI `--film-media-scatter declared|off`）是介质自身的散射（乳剂
  散射与相纸成像散射，由 MTF 拟合），属于所声明的介质而不是观感量："**按声明 ·
  默认**"下只要光学链启用就按编译 profile 生效，与三条滑杆无关；"**关闭**"是
  测量工具隔离单算子的口径，日常不用。
- **显影配方**（CLI `--film-development`）：特性曲线按哪种显影求解。"**实测默认**"
  （`measured_default`）是数据手册显影，三个扰动锁定为 0；"**自定义显影**"
  （`editorial_custom`）露出三条有界滑杆，报告如实标注编辑显影：**显影对比**
  （−0.5…0.5，CLI `--film-dev-contrast`）绕中灰锚缩放特性曲线的 logE 轴——推冲/
  拉冲的对比维度，中灰不漂由构造保证；**显影灰雾**（0…0.3，CLI `--film-dev-fog`）
  给三层均匀加密度——化学灰雾的真实行为就是整体提亮，工具不做隐藏补偿；
  **显影色密度**（−0.5…0.5，CLI `--film-dev-density`）绕中灰锚缩放显影出的染料量，
  中灰同样不漂。两条联动规则与 CLI 一致，服务端同样校验：自定义显影要求灰阶
  中性化为"数据手册漂移"（有界中性化的 cast 曲线按实测显影求解），GUI 自动切换
  并在状态栏提示，其它中性化选项置灰，CLI 需显式配 `--film-neutralization native`；
  自定义显影与"随胶片曝光重定时"互斥（重定时的 τ 表同样按实测显影求解），GUI
  把重定时置灰并回到固定，固定与自定义 timing 都可以配。
- **胶片压缩**（0…1，默认 0，CLI `--film-compression`）：乳剂之前对场景亮度 EV
  做的 C1 饱和压缩——在 knee 之上把数字硬高光平滑地压进负片的宽容度，声明为
  editorial 桥接；0 是严格恒等。大于 0 后再露出两条滑杆：**压缩 knee**（中灰之上
  0…6 EV，默认 2，CLI `--film-compression-knee`）定压缩从哪一档开始；**高光色密度**
  （0…2，默认 0，CLI `--film-highlight-density`）让被压缩的高光向保亮度的中性收敛，
  即负片高光染料密度趋满的观感。后者只在压缩 > 0 时有意义：压缩为 0 时 GUI 把它
  归零，CLI 与服务端拒绝非零值。

以上显影配方、胶片压缩、介质散射、光学种子都是接管专属，只在"显影分工"选接管时
显示；切回观察时全部复位为默认，不会有陈旧值悄悄带进载荷（服务端也拒绝观察模式
下的非默认值）。导出文件名只在非默认时附加标记，以免覆盖默认渲染：自定义显影
`dev-c…f…d…`、胶片压缩 `comp{c}k{knee}`（高光色密度 > 0 时再加 `hd{x}`）、介质
散射关闭 `scatteroff`、显式种子 `seed{n}`。

### 放大机色头（仅负片）

彩色负片没有"自己的颜色"——底片只是中间记录，最终颜色是在放大机下由**人**
决定的：色头上的 Y/M 分色滤镜档位就是那次决策。选中任一**负片**预设
（Portra/Gold/Superia/Vision3 系等）后，成像卡会出现两条滑杆：

- **单位是真实暗房单位**：CC 滤镜密度，0–200、步进 5；30CC=0.30 光学密度
  ≈该分色 1 档印相曝光衰减。改档位后按暗房惯例自动重解曝光时间，中灰亮度不变；
- **方向背暗房口诀**：成片偏什么色，加什么色的滤镜——偏黄加 Y（黄滤镜吸收
  蓝光、少曝相纸蓝敏层、少生成黄染料），偏品加 M；
- **实用尺度**：真实暗房的精修步长是 2–10CC，30CC 以上属于"色彩大错"级别的
  粗调，量程到 200 只是复刻硬件拨轮的行程。胶片教程里的实拍：Y +5CC 明显
  减轻暖罩，Y +10CC 恰好穿过中性；M 档同尺度更烈，M +10CC 已明显推向绿——
  品绿轴的步子要比黄蓝轴再小一半；
- 响应模拟真实印相光路，改档位后亮度自动保持不变（实现方式见
  [架构文档](ARCHITECTURE.zh-CN.md)）；
- **反转片（Velvia/Provia/Ektachrome/Kodachrome）两条滑杆置灰归零**，旁边
  写明原因——幻灯片自身就是显示介质，物理上不存在印相环节；
- **接管模式下要先把印相 timing 切到"自定义"**：固定/重定时的印相由联合求解
  决定，色头此时置灰归零并提示；切到自定义后色头作为 modelled Δτ 参与手动
  印相。观察模式下任何负片都随时可用；
- 两档都在 0 时和不启用完全一致（预设出厂的中性印相决定）。

**镜前滤镜**（RAW 解码卡）是配套的独立选项：按柯达出版的 Wratten 滤镜参数模拟
镜头前的转换玻璃（85B 日光转钨丝、80A 钨丝转日光等），用于复刻"钨丝卷 + 85B
拍日光"这类历史工作流。滤镜没有强度滑杆——玻璃没有半片。

## 六、界面上其他的 EV

- **曝光 EV**（曝光卡的滑块）：整体提亮/压暗，+1 = 亮一档。0 保留拍摄时的亮度关系。预览上的"RAW 满阱"标记不随它变化——那标的是解码证据（第三节）。
- **亮度参考**（按钮）：让工具测量主体亮度并自动对齐到标准曝光，同时避免高光溢出。相当于"帮我曝光一次"，结果会写回曝光滑块，可以再手调。
- **HDR 余量上限**（输出卡）：你的屏幕/用途最多允许 HDR 比纸白亮几档，是**天花板不是目标**——实际用多少由"可挣余量"决定，两者取小。默认 +3.0（约对应 800 nit 屏幕）通常不用动。
- **HDR latitude 旋钮**（输出卡的折叠区,默认收起=auto）：三个主观量——**色度自由度 ρ**（证据置信满格时高光允许多少逐通道色彩,默认 0.5）、**白点余量**（白端点在可靠尾部之上几档,默认普通 0.30/稀疏光源 0.50）、**肩起点**（HDR 肩部从主体上方哪一档开始,默认 0.20/0.00）。默认值是数学化的政策口径;这三个量测量决定不了,所以开成旋钮。证据门控（剪切/噪声/色域压力）始终乘算,不被旋钮绕过。CLI 对应 `--hdr-rho` / `--hdr-white-margin` / `--hdr-shoulder-start`。
- **层间放大 β**（成像卡，接管模式下"层间放大"选"自定义 β"后出现）：显影耦合的色差放大量。默认"声明"=该卷 modelled 表值（0.32–1.05）;自定义后报告会标 editorial dial。CLI 对应 `--film-interimage custom --film-interimage-beta`。
- **压缩 knee**（成像卡，接管模式下"胶片压缩"大于 0 后出现）：饱和压缩从中灰之上第几档开始，0…6 EV，默认 2；压缩只作用于 knee 之上的场景亮度。CLI 对应 `--film-compression-knee`。

## 七、明暗卡：端点模式与趾部/肩部

完整的修图顺序教学（范围 → 定位 → 色彩补偿，含样张对比图）见
[修图工作流说明书](EDITING_TUTORIAL.zh-CN.md)。

- **端点模式**：曲线的黑点/白点从哪里来。**场景自适应**（默认）追随这张照片的
  亮度百分位——多数照片正确，但大面积深阴影（逆光桥底、暗巷）可能被当
  成"黑"。**证据界**（传感器实测范围）改为钉在传感器实测上：黑点 = 实测噪声底 EV（有该机型先验时
  用先验读出噪声，来源更准；没有先验时用单帧估计并如实注记），白点只信可靠 RAW
  尾部（重建出来的高光不算数；证据缺席时如实回退并注记）。曝光锚不变（0 EV 仍
  映射 18% 灰），所以画面整体亮度不跳。
- **趾部收黑**（EV 滑块）：曲线在哪个 EV 落到"近黑"。向左把这个点推深——更深的
  阴影保持可读、更晚坠向黑点；通过重解趾部形状实现，**不移动黑点、白点和天空
  高光**。向右更早收黑、暗部更紧。
- **肩部收白**（EV 滑块）：曲线在哪个 EV 升到"近白"（黑地板到白点跨度的 90%）。
  向右推迟收白——高光层次更晚合并、滚降更柔；向左提早收白、肩部更硬。通过重解
  肩部曲率实现，**不移动黑点、白点和肩部起点**。
- **暗部过渡 / 高光过渡**（−1…+1 滑块）：趾部与肩部的**微调档**。与趾部收黑/
  肩部收白不同，它们不指定 EV 坐标，只把趾部/肩部段的弯曲程度乘一个有界系数
  （满幅约 ±37%），黑点、白点、中灰锚全部不动。**设计上就是克制的**：满幅拉动
  在成片上的峰值差异只有几个码值（实测约 3–9/255，集中在深阴影或高光滚降的
  一个亮度窗口里），整图逐像素 p99 通常不超过 10/255——预览里基本看不出来是
  正常表现，不是滑条坏了。满幅暗部过渡约等于趾部收黑 0.6–0.7 档；满幅高光过渡
  约等于肩部收白 0.1 档以下。想要看得见的移动，直接用趾部收黑/肩部收白。
  另外，肩部没有弯曲余地的照片上（见修图说明书"肩部收白纹丝不动"一节），
  高光过渡和肩部收白一同失效，满幅差异不足 1/255——同一个几何原因。
- **高光褪白**（颜色卡，−1…+1 滑块）：只调整**接近显示白的彩色像素**的色度——
  向右更早褪向白，向左保留更多颜色；亮度完全不动。中性（无色）的亮部数学上
  零变化，所以画面里没有"又亮又有颜色"的内容（晚霞云、彩色灯罩之类）时它完全
  不可见；有这种内容时满幅拉动单通道最多约 15/255。**HDR 输出下它被禁用**
  （HDR 的高光色彩几何独立处理，导出时该值强制为 0）；暗部过渡在 HDR 下照常
  生效，高光过渡则不参与 HDR 高光的形状（HDR 肩部从中灰上方独立求解）。
- 明暗卡底部的实测行会显示**实际生效的值**（趾部收黑/肩部收白各在几 EV、端点
  来源），越界的请求会被钳到最软/最硬的合法曲线，显示的永远是实际生效的数字。
- **拿不准高光问题该归谁**：先开预览卡的"RAW 满阱"（第三节）。RAW 离满阱还远、只是
  渲染太亮，肩部收白/高光过渡和 EV 都有效；RAW 已经三通道溢出的区域，任何曲线
  设置都变不出层次。

## 八、两个实时直方图

预览时界面上有两个直方图，口径不同、各贴各的功能，随每一帧预览同步更新：

- **场景 EV 直方图**（曝光卡内，EV 滑块下方）：横轴是相对 18% 灰的场景亮度档位（−10..+4 EV），纵轴是对数计数。它画的是**可靠场景亮度**——与曲线规划完全同一份采样：RAW 剪切的样本和被地板钳制的黑样本都被剔除，所以你看到的人口就是渲染决策看到的人口。注记线：**黑/白**是实际生效曲线的两个端点（EV 滑块动时端点不动、人口整体平移，可以直观看到人口越过端点被压掉）；**0EV** 虚线是 18% 灰基准；**p99.99** 是可信的最亮信号（HDR 预算的依据）。可靠证据不足时（大面积剪切等），p99.99 线如实不画，不用别的数字顶替。
- **显示码值直方图**（预览卡内，预览图下方）：从已渲染的 1920px 预览帧统计 RGB 三通道加 luma，0–255 码值，对数计数。它回答"这一帧实际输出长什么样"——顶白、断层、堆黑一眼可见。选择 HDR 输出格式时，画的是 SDR 底图的直方图，并在角上注记"HDR 已挣余量 +X.X EV"（场景证据不足时该注记同样不画）。

两个直方图目前是纯显示，无悬停、无框选。

预览卡上还有一层不是直方图、但同样按帧叠加的东西："RAW 满阱"标记（第三节）。它与显示码值直方图互补：直方图的顶白告诉你输出撞了 255，过曝层告诉你 RAW 本身是否早就撞了满阱——前者能靠曝光和曲线救，后者不能。

## 九、压缩核心是什么，怎么选

RAW 记录的亮度范围远超屏幕能显示的范围，"压缩核心"就是把前者装进后者的方式——它决定照片的整体观感，尤其是高光的颜色表现。

| 选项 | 一句话 | 什么时候用 |
|---|---|---|
| **AgX · 默认** | 电影级的收高光方式：亮部自然褪向白色，颜色不会又艳又假 | **不确定就用它**，95% 的情况 |
| **RAW 门控 · 保真** | 和 AgX 同款亮度，但颜色处理的强度由 RAW 证据逐像素决定：传感器真实测到的颜色尽量保留 | 想要更"忠实于传感器"的颜色时；仅 LibRaw 解码可用 |
| **场景 C1 · 仅亮度** | 只压亮度、完全不动颜色比例 | 对照组：想看看"AgX 的颜色处理到底做了什么"时切来对比 |
| **固定亮度曲线 · 诊断** | 固定曲线，不看场景 | 排查问题用，日常不用 |

后两个是对照/诊断工具，不是给成片用的。

## 十、输出：格式与交付档

**格式**：
- **SDR JPEG**——普通照片，哪里都能看；
- **HDR gain-map · JPEG**——推荐的 HDR 格式。照片里同时装了普通版和高光增强信息，支持的屏幕（iPhone、Mac、Android 15+）上高光真的会亮起来，不支持的地方自动显示普通版，不会出错；
- **HDR gain-map · HEIC**——同样内容的 HEIC 容器。**实测它并不更小、画质还略差**，只有下游明确要求 HEIC 时才选。

**交付档**：
- **Archive · 保真**——最高质量（约 60MB/张），当高质量留底用；
- **Share · 流媒体**——发布用（约 11–27MB/张），肉眼基本无差、HDR 信息完整保留，**最大的照片也在微信"原图"25MB 限制之内**。

**发微信的注意事项**：聊天里必须勾"**原图**"，HDR 才能到达对方（iPhone 微信看原图有完整 HDR 效果）；**朋友圈一定会被压缩成普通照片**，这是微信的行为，任何工具都绕不过。重要交付走"文件"方式发送最保险。

**导出后看导出报告**（GUI 面板名"投递报告"）：预览图上方那个可折叠面板，写着这次导出的实际情况——文件多大、HDR 实际用了几档、压缩造成的误差有多小。每张导出的文件都经过了自动校验，校验不过的文件不会被保留。它列的只是 HDR 容器的实测事实，不是分析报告——分析报告在命令行用 `--report` 打印（第二节末尾）。

**附带分析图**（输出对话框里的勾选框）：导出时顺带画一张六面板诊断 PNG，等价于命令行的 `--scan`。它需要可选依赖 matplotlib（`pip install 'dngscan[scan]'`），缺失时这个勾选框置灰并写明原因，而不是等全尺寸分析做完才失败。

## 十一、哪些选项会自动置灰

GUI 的原则是：**需要特定环境或资产的选项，在缺失时置灰并把原因写在旁边**，而不是让你选了之后导出失败。目前按这个原则处理的有：

- **解码器 · Apple RAW**——需要 macOS 上的 Core Image（PyObjC Quartz），没有就锁定 LibRaw；
- **HDR gain-map · JPEG / HEIC**——页面加载时探测一次 HDR 后端（`/hdr-status`，后端做回读验证），没通过就置灰并显示原因，已选的格式切回 SDR；
- **RAW 门控 · 保真**压缩核心在 Apple RAW 下不可用——它靠逐像素 CFA 证据决定色彩路径，Core Image 没有这份证据；
- **胶片解释**的参考印相/自定义与**解释变体**的扫描对照——只对做了配方/资产的卷开放（第五节）；
- **印相 timing** 的重定时/自定义与**色头**——反转片一律固定、色头置灰归零；接管模式下色头还要求自定义 timing（第五节）；
- **自定义显影**（接管模式的显影配方）——灰阶中性化锁定为"数据手册漂移"，其它中性化选项置灰、切换时状态栏提示；印相 timing 的"随胶片曝光重定时"置灰并回到固定（第五节）。自定义 timing 同样把中性化锁到数据手册漂移；
- **附带分析图**——需要 matplotlib（第十节）；
- **RAW 满阱**——Apple RAW 解码没有逐像素 CFA 证据（第三节）。

还有两处是**提示但不置灰**：Apple RAW 的 RAW 9/8/7 版本是逐文件探测的，文件不支持时在提交前拦截并让你选择（第一节）；固定色温白平衡在没有颜色标定的文件上会退化为拍摄值，检测参数卡上用 ⚠ 标出。

另有几处是按状态**隐藏而不是置灰**：CI 尺度只在解码器为 Apple RAW 时出现；显影配方、胶片压缩、介质散射、光学种子只在接管模式出现，切回观察即复位；压缩 knee 与高光色密度只在胶片压缩大于 0 时出现。

## 十二、常见问题

**导 HDR 时报"可靠高光尾部不支持任何 HDR 余量"？**
这张照片没有测到真实的高光内容（检测参数里"HDR 可挣余量"为 0）。这不是故障——一张没有亮部的照片做成 HDR 也不会有任何区别，改导 SDR 即可。

**选 Apple RAW 后弹出提示说这个文件只支持 RAW 8？**
你的相机/文件不在 RAW 9 的支持范围。按提示选择用旧版本继续，或改回 LibRaw，两者都能正常出片。

**预览和导出会不一样吗？**
预览用低分辨率代理以求快，构图和色调一致；锐度、噪点观感以全尺寸导出为准。导出状态里标"全分辨率真值"的数字才是最终值。

**HDR 效果在哪里能看到？**
用 macOS 预览/访达、iPhone 相册、Android 15+ 相册或 Chrome 打开导出的文件。普通显示器/老系统上它就是一张正常的 JPEG。

**质量和色度采样为什么有时不能改？**
Archive 档按定义锁定最高质量；HDR 格式下色度采样由系统编码器按质量自动决定，工具如实显示而不是假装可调。
